## What the Factory Configuration Got Wrong

Read straight off the flight controller before any changes:

- **Arm was on AUX1, beeper on AUX4** — exactly reversed from Crafty. This was the
  single most important thing to fix, because it is pure muscle memory and getting
  it wrong is a safety problem.
- **Crashflip sat in aux slot 4 on AUX3**, where Crafty uses slot 5 on AUX5.
- **No prearm entry and no OSD-profile adjustment**, both of which Crafty carries.
- **Rate type was explicitly `BETAFLIGHT`** with a 110 / 74 / 0.30 curve, against
  Crafty's ACTUAL 170 / 550 / 0.35.
- **Throttle was linear and unlimited**: `thr_mid 30`, `thr_expo 0`, `thr_hover 34`,
  no scale limit. Crafty runs 40 / 35 / 44 with an 80% scale limit, which is why the
  factory Air65 felt twitchy in the low half of the throttle stick.
- **Telemetry feature off**, no pilot name, no FPV camera mix.

## Adjustments Made

Factory state backed up first, then 67 commands applied in a single saved session:

```bash
python tools/backup_restore.py --backup --name air65_factory
# ... aux / adjrange / feature / set / vtx / rateprofile commands ...
python tools/backup_restore.py --backup --name air65_configured
```

Ported from Crafty:

- Full switch layout, including arm back on AUX4 at `1800`–`2100`.
- ACTUAL rates at 170 / 550 / 0.35 on roll and pitch, 120 / 400 / 0.25 on yaw.
- Throttle curve and the 80% scale limit.
- `fpv_mix_degrees = 10`, `pilot_name = HansF`, `feature TELEMETRY`.
- All 32 OSD element positions plus the warning and stat bitmasks, and
  `vcd_video_system`, which was later reverted (see below).
- `crashflip_rate 30`, `crashflip_auto_rearm ON`, `vtx_low_power_disarm ON` and the
  four-step VTX power switch table.

Left alone on purpose: PIDs, filters, `motor_idle`, board alignment, accelerometer
calibration, and the VTX frequency. The Air65 stays on Raceband 1 and Crafty on
Raceband 3 so the two do not clash when both are powered.

## Verification

`aux`, `adjrange` and the whole `rateprofile 0` block now come back byte-identical
to Crafty's backup. `rates_type` is absent from `diff`, which proves ACTUAL is the
firmware default and that the Air65 sits exactly where Crafty sits.

Pre-flight audit: bi-directional DShot **PASS**, receiver CRSF **PASS**, blackbox
flash **PASS**. One warning, `RXLOSS DSHOT_TELEM`, which is expected with the radio
off and no battery connected.

## Correction — Video System

Copying Crafty's OSD block initially set `vcd_video_system = AUTO`. The BETAFPV
notes that shipped with the board say to pin it to `NTSC`, alongside
`osd_displayport_device = MAX7456`, or the OSD may show nothing. Reverted to `NTSC`
the same session and confirmed by reading it back.

This board also runs a customized BETAFPV build of the Betaflight developer firmware
because its gyro, a BMI270 here, is not yet supported by official releases. Stock
Betaflight must not be flashed onto it. See
[BETAFPV FC Gyroscope & Firmware Notes](/reference/betafpv-fc-gyro-firmware-notes.html).
